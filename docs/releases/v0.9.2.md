# wot-0.9.22-offline-battles v0.9.2

This release includes all updates since v0.9.1 for the Chinese HD
World of Tanks 0.9.22.0.1 #1513 client.

## Personal missions and battle results

- Fix HT-4 across all four operations by counting damaged or destroyed internal
  modules and knocked-out crew. Damage and destruction recorded in the same
  transition count once; a new critical hit after repair can count again.
- Fix TD-2's destroyed-internal-module and crew requirements. Its additional
  objective now uses the vehicle's final internal damage state, including
  repairs, rather than its accumulated damage history.
- Fix LT-5 by crediting spotting-assisted kills to the eligible observers when
  the enemy is actually destroyed. Crew knockouts and final damage shares
  rounded to zero are included; earlier spotting damage alone does not credit
  a later unassisted kill.
- Complete MT-11 evaluation across all four operations: ramming damage,
  ramming kills, surviving the killing collision, and destroying the required
  higher-tier target. Each operation's main and additional objectives retain
  their installed requirements.
- Record both vehicles' actual HP losses and survival outcomes from the same
  collision for player/player, Bot/player and Bot/Bot rams. A later shell kill
  does not erase earned ramming damage, and survival of a different collision
  cannot satisfy the objective.
- Support the shared mission conditions for surviving a killing ram, dealing
  more ramming damage than received, and minimum vehicle-tier differences.
  The same evidence is available to other installed missions using them.
- Preserve these statistics through server results, saved receipts, client
  normalization and mission settlement. Repeated reports and repeated
  settlement do not award progress twice. Friendly targets are excluded, and
  old or incomplete histories do not invent missing evidence. Mission
  thresholds, rewards and vehicle collision damage rules are unchanged.

## Garage and barracks

- Fix the barracks failing to display or filter crew because its sorting
  callback returns a Python 2 long integer instead of an int.
- Normalize comparison results while preserving the client's normal ordering,
  crew identities, native prices and price formatting. The shared correction
  also covers other fitting-item lists using the same comparator.

## Hydraulic suspension and terrain support

- Correct downhill support for player vehicles and Bots on the affected legacy
  suspension path. Preserve downhill momentum in both forward and reverse,
  and settle reachable support without repeatedly opening a gap above it.
- Apply the accepted physical chassis attitude together with support height,
  avoiding the reproduced nose penetration at a slope-to-flat transition.
- Derive support height and attitude from the same sampled chassis footprint
  for hydraulic vehicles crossing ledges and uneven surfaces. This addresses
  the reproduced stale tilt and centre-height mismatch reported in Paris.
- Preserve loss of support at cliff edges and normal airborne gravity. These
  corrections add no movement waits or new drive/brake coefficients.

## Track direction and Siege transitions

- Correct the shared left/right belt speeds during hull rotation. Positive
  rightward hull yaw now advances the left track and retreats the right track.
  The correction applies to pivots, forward turns and reverse turns, including
  every Siege-capable vehicle in both modes and local/Bot/remote presentation.
- Brake before switching in either direction between Travel and Siege modes.
  A moving vehicle retains its current mode and decelerates through the
  existing braking physics. Only after longitudinal and traverse motion have
  stopped is the switch requested and its normal transition timer started.
- Apply the same sequence to Bots. Failed requests remain retryable; cancelling
  a queued request preserves current motion. Airborne momentum cannot be
  erased to start a transition. No new braking coefficient or timer is added.

## Siege-mode obstacle destruction and trees

- Fix powered destruction eligibility in Siege mode by using the mounted
  travel configuration's directional drive capability. Actual movement speed,
  traverse, mass and geometry continue to come from the active mode.
- Apply the shared contact policy to forward/reverse movement, hull pivots and
  falling columns for players, the hidden worker and Bots. Exact contact,
  object health/scale checks and solid backing walls remain enforced.
- Correct tree sweeps to accept the client's indexed hull vectors, preventing
  an unsupported vector-slicing operation from dropping the complete sweep.
- Fix registration after mode-excluded entries in compacted map filename
  lists. Valid trees and models later in the same chunk can now register,
  addressing the diagnosed missing Prokhorovka railside poplar entries.
- Preserve the directional speed-limit magnitude used by reverse pivot
  contacts without changing the vehicle's signed movement speed.

## Map collisions and capture

- Murovanka: remove proved residual original fence collision only inside the
  registered, already-destroyed fence's bounds in a repaired map chunk.
  Replacement geometry, live objects and backing walls remain solid.
- Prague: remove the captured residual workshop-door surfaces only within the
  already-broken door panels. Intact building components and walls retain
  their collision.
- Mittengard: use the map's authored 30-metre capture radius for both bases.
  Player occupancy, Bot occupancy and defence threats use the same radius.
  Navigation baking now carries decoded capture circles through to battle
  setup; maps without decoded radii retain their existing behaviour.

## Diagnostics and validation

- Add bounded local-tree records covering sweep geometry, authored placement,
  registration, health and destruction/presentation state. Keep this logging
  compatible with the Python 2.7 JSON encoder.
- Add continuous hydraulic-motion summaries in both travel and Siege modes,
  including timing, speed loss, missing travel, height and attitude changes.
- Add shot-correlated track/hull outcomes to identify whether a front-wheel hit
  reached a hull plate, penetrated it and proposed both track and vehicle
  damage. Integrated regressions cover both player and Bot shots; penetration
  and track-damage rules are unchanged.
- Include path position, nearby waypoints, planned goal and navigation status
  in Bot stall reports. Diagnostic sampling adds no native collision queries
  or movement delays.
- Expand regression coverage for all affected mission families, saved receipt
  restart and exactly-once settlement, barracks sorting under Python 2.7,
  hydraulic support, tree registration, Siege contacts, track directions,
  both-way brake-before-switch transitions and map boundaries.

## Known issues and remaining verification

- Drowning warnings still incorrectly map the visual water sensor's shallow
  water contact to the caution icon. Its fallback also confuses a two-dimensional
  carrying footprint with a height. These defects are identified, but the exact
  0.9.22 warning-height rule remains unverified and is not repaired in this release.
- Sustained damage from stacked vehicles, wrecks and detached turrets remains
  unimplemented. The requested upper/lower and alive/wreck rules are recorded
  in the compatibility review; the retail damage law has not been recovered.
- Continuous Swedish TD hitches in both modes, the reported front-wheel
  track-break/HP-damage issue, Paris E-line Bot behaviour and Murovanka faces
  outside proved object bounds remain under investigation.
- The repaired mission, barracks, tree, Siege-contact, track-direction,
  brake-before-switch and hydraulic-support
  paths still need acceptance in the exact Windows game client. Automated
  tests and package inspection do not establish native gameplay behaviour.
- Mission fixtures use the available 0.9.22 reference definitions, including
  RU #788 data for MT-11. Runtime evaluation continues to read the installed
  CN #1513 definitions; this release does not replace quest resources.

## Version and installation

- Update the launcher, server, executable file versions, client mod, wotmod
  metadata, diagnostic version and package name to 0.9.2. This is the mod's
  version; the supported game client remains CN HD 0.9.22.0.1 #1513.
- Download `wot-0.9.22-offline-battles-0.9.2-Windows-x64.zip`. Close the old
  launcher, server and game, extract the complete ZIP into an empty folder,
  and run `wot-0.9.22-offline-battles.exe` from that folder.
- Select the existing supported game folder and let the launcher install the
  bundled update. Existing saves and user configuration are preserved.
- The Windows x64 package includes these complete English notes as
  `UPDATE_NOTES.md`. The release workflow runs the client and launcher suites,
  builds the client with Python 2.7, and checks the executable architecture,
  version identity and nested package contents before publication.

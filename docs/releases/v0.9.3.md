# wot-0.9.22-offline-battles v0.9.3

This release includes all updates since v0.9.2 for the Chinese HD World of Tanks
0.9.22.0.1 #1513 client, including the gameplay follow-up and both interface-audit
fixes from PRs #14, #15 and #16.

## Aiming and the server reticle

- Connect the stock **Use server reticle** option to real hidden-worker feedback.
  Players retain the choice: disabled uses the native local marker; enabled uses
  the worker result returned through the LAN server. The setting is saved by the
  original client.
- Capture the native stabilized vehicle pose, turret angle, gun elevation and
  dispersion with an ordered input. Compute the shot origin and direction from
  the installed vehicle descriptor in the worker, rather than echoing the visible
  client's HUD ray and calling it server feedback.
- Use the same input-bound geometry calculation for feedback and an accepted
  trigger. Later replica movement cannot redirect an already accepted shot.
  Native gun laying and dispersion remain client input evidence, not a replacement
  worker-side aiming simulation.
- Preserve the currently loaded shell's velocity in each feedback sample. Queuing
  another shell cannot rewrite a result that was computed for the loaded shell.
- Reject missing, stale, wrong-round and wrong-worker feedback. Do not substitute
  a local ray when a valid server marker is unavailable.
- Fix delayed server-marker feedback overwriting current local dispersion.
  Preserve and restore the native dispersion storage at the display boundary,
  including exceptions and native-owner replacement. The marker still displays
  the reply, while the next input and immediate shot retain current local bloom.
- Keep marker selection independent of ammunition, reload and projectile admission.
  This option does not reduce hidden-worker frame time or fix delayed tracers and
  hit confirmation.

## Vehicle movement, braking and hydraulic suspension

- Prevent track-powered steering while airborne. Preserve existing angular
  momentum and world-space forward/lateral momentum instead of bending the flight
  path when the hull rotates. Airborne wall contact removes the blocked velocity
  component without inventing a rebound.
- Restore deceleration when the accelerator is released, following the supplied
  retail test. Explicit braking remains stronger; airborne inertia is preserved.
- Replace the previous 1.05 downhill speed envelope and artificial overspeed
  build-up/drag with gravity-driven overspeed and an approximate 1.35 envelope.
  Engine acceleration still stops at the installed rated speed. Forward, reverse
  and the active Travel/Siege mode use their own directional limits. The 1.35
  value is the user's requested empirical approximation, not a recovered universal
  retail coefficient.
- Respect the installed chassis `rotationIsAroundCenter` flag and actual track
  spacing. Vehicles requiring a stationary inner track pivot around it in the
  relevant low-speed manoeuvre; vehicles supporting centre rotation retain it.
- Keep hull translation, left/right track animation, curved collision sweeps and
  terrain-support rollback consistent with the selected pivot. Cover trees,
  native/static obstacles, other vehicles and detached turrets without relaxing
  collision checks.
- Correct hydraulic vehicles retaining stale native world offsets as local Siege
  offsets. Derive rendered and collision poses from the current chassis placement
  and the installed hydraulic pivot.
- Evaluate limited-gun hull autorotation in the pitched/rolled vehicle's local
  coordinates, rather than subtracting world yaw. Preserve the original
  autorotation and hull-lock controls.

## Water warnings and drowning

- Replace shallow visual water-contact flags with the requested hull-based
  gameplay rule: no warning below half the hull height, a caution warning above
  half the hull, and the ten-second countdown above the top of the hull.
- Use actual descriptor hull geometry transformed by current vehicle attitude,
  including hydraulic body pose. Apply the same geometry to players and Bots.
- Keep visual splashes separate from the gameplay warning threshold. This rule is
  based on the supplied retail observations; it is not described as a recovered
  proprietary server formula.

## Bot navigation, traffic and artillery

- Follow up the Airfield `20260922-175318` report from build
  `colorfulmeans-35710905364-1`: the prior ignore policy still hydrated each
  prop and exhausted its recast budget on overlapping clay fences. Planning
  now rejects original destructible materials 71 through 85 in the **first**
  native callback. Route, approach and support queries no longer depend on a
  prop's catalog registration, crush energy or the number of soft layers.
  The exclusive sentinel 86, damaged replacements, terrain and hard backing
  walls stay visible to the complete native query.
- Sample the real ground below destructible roofs with the same planning
  filter. Preserve terrain grade, missing-support and water checks. Physical
  hull movement, vehicle contact, suspension and destruction still require
  their existing collision and kinetic evidence.
- Keep limited-traverse gun aiming from reversing a route or retreat turn,
  or taking control during navigation waits and recovery. Explicit combat
  engagement and stationary firing holds retain their aiming behavior.
- When a native collision rejects a requested turn, brake its coupled drive
  command instead of accelerating along the old heading into the hillside.
  Feed the actual failed angular sweep back to recovery at that same pose,
  so it can wait, choose an independently checked straight reverse exit, and
  retry turning after moving away. Keep the no-progress timer and add the
  rejected-turn cause to movement diagnostics.
- Cover the reported M46 clay-fence ray, hard surfaces behind props, cold
  registration, exhausted recast budgets, SU-122-44 retreat headings and
  rejected-turn motion in controlled regressions. These tests do not claim
  a Windows native-engine gameplay replay.
- Request explicit braking for route arrivals, tactical holds, traffic yields and
  TD/SPG aiming. Derive stopping distance from the same brake law, signed speed
  and slope. Validated forward/reverse escapes clear inherited brake requests.
- Fix finite traffic-yield checks repeatedly demanding a full escape corridor
  after most of the manoeuvre is complete. Check the remaining endpoint distance
  while preserving the complete swept hull and native motion proof. This covers
  the recorded Himmelsdorf departure deadlock.
- Add validated rear escape candidates when the complete forward fallback fan
  fails, addressing the recorded trapped Airfield position. Rear paths use the
  same terrain, hazard and collision checks.
- Recheck a baked corridor after a genuine static-probe refusal, including cases
  where zero throttle prevents a movement contact. Traffic holds or failed probes
  alone do not reclassify terrain as a solid obstacle.
- Invalidate private join/recovery paths as well as shared paths when new wrecks
  occupy them. Resume advancing toward the actual capture objective after the
  final route segment instead of returning to an earlier waypoint.
- Correct SPG moving-target proof latency prediction when a changed lead creates
  a different-length ballistic arc. Use observed time per segment and the new
  arc's actual workload; retain the shared query budget, freshness limit, frozen
  launch trajectory and random dispersion.

## Map collision and diagnostic evidence

- Westfield: remove retained bevel/top collision faces only when ownership is
  proved inside an exact, already-destroyed component box in a remapped chunk.
  Intact objects, backing geometry and unproved faces remain solid.
- Add bounded native slot/category/mapping evidence for remaining Westfield
  blockers. Ten of the eleven contact witnesses in the supplied report are
  covered; the unproved out-of-bounds witness remains blocking.
- Improve wreck-pushing reports to distinguish track hold, a world blocker,
  missing support, a support step and actual movement. Do not change unverified
  wreck friction or add a distance cap.
- Preserve bounded takeoff/landing transition samples with preceding and current
  support/motion evidence, in addition to worst-frame hydraulic samples. These
  diagnostics improve investigation; they do not claim all Swedish TD hitches are
  fixed.

## Personal missions and persistent battle results

- Fix LT-6 equipment evidence using the optional devices frozen at battle start,
  including normal optics, bond optics and binoculars. Later garage edits cannot
  change that battle's equipment condition.
- Fix LT-9 detection evidence before the observer has ever been spotted. Consider
  both teams' simultaneous visibility transitions before crediting the event.
- Fix MT-12 ignition evidence: record each accepted fire ignition once, while a
  genuine new ignition after extinguishing can count again.
- Fix TD-4 visibility conditions at the relevant damage/kill event, using actual
  enemy visibility rather than the delayed sixth-sense display.
- Fix HT-5's `distance=0` condition to mean damage inside the current effective
  view range, not unlimited distance. Freeze actual distance and the latest
  accepted effective view radius with the event, including crew/equipment state.
- Cover all four operations using the installed mission requirements. Preserve
  the additional event evidence through server receipts, client normalization,
  save/restart and settlement; retain legacy receipt reads without inventing
  missing historical evidence. Mission thresholds and rewards are unchanged.

## Consumables, inventory and request handling

- Stop consuming the permanent Removed Speed Governor when it is enabled or
  disabled. Its toggle and existing gameplay effects remain unchanged; it no
  longer disappears from the vehicle or causes an erroneous replacement purchase.
- Charge food/rations and fuel once from the accepted battle-start loadout,
  including participants who later disconnect. Cancelled loading clears these
  round-local records; infrastructure aborts without a settlement receipt do not
  create inventory charges.
- Preserve use-based settlement for repair kits, first aid kits and extinguishers:
  unused items are not consumed, and repeated use within one battle consumes only
  one item. Replayed requests and repeated settlement do not charge twice.
- Share supported module/crew target names between client and server. Reject an
  unsupported target before sending it or allocating an outgoing request number.
- Give an identifiable, contiguous consumable request an explicit accepted or
  rejected terminal result even when its payload is invalid. A rejected request
  no longer leaves a permanent sequence hole that blocks later valid inputs.
- Continue rejecting invalid identity/round/type, invalid sequence numbers, gaps
  and conflicting retransmissions. Exact duplicates do not execute twice. No
  item prices, cooldowns, attribute factors or historical inventory compensation
  are changed.

## Waiting-room tier selection

- Add `0/+1/+2` and `-2/-1/0` tier presets.
- Make random tier selection choose one contiguous one-, two- or three-tier
  window that accommodates all configured human vehicle tiers. Automatic Bot
  substitutions stay inside the chosen window.
- Preserve explicit human selections and manual lineups. Existing offline
  tier/class proportions remain unchanged; this is not a complete reproduction
  of the retail 3/5/7 matchmaker.

## Validation and remaining limitations

- Expand regressions for airborne momentum, hydraulic poses, track pivots,
  downhill speed, braking, low-FPS Bot departures and recovery, SPG planning,
  water thresholds, mission event evidence, consumable settlement and native
  reticle shared-state ownership.
- Build the client bytecode with CPython 2.7.18 and the launcher/server for Windows
  x64. The release pipeline runs the client and launcher suites and verifies
  executable versions, architecture, bundled build identity and nested packages.
- Native Windows #1513 gameplay, frame pacing and visual behaviour still require
  in-game verification. Automated tests are not a claim that every reported
  gameplay issue has been resolved.
- Hidden-worker low-FPS firing/tracer/impact delay is not fixed by this release.
  No new immediate-fire prediction or projectile catch-up redesign is included.
- Continuous Swedish TD stutter, sustained crushing damage from stacked vehicles,
  wrecks and detached turrets, and moving handbrake drift remain unresolved.
  Unproved map collision faces remain blocking.
- HT-5 view-range evidence retains the existing visibility observation cadence;
  a state change can fall within one normal observation interval. Mission test
  reference data do not replace the installed CN #1513 definitions.
- The two unconfirmed consumable presentation issues (native governor stage
  interaction and dedicated activation audio) remain unchanged.

## Version and installation

- Update launcher, server, executable file versions, client mod, wotmod metadata,
  build identity and package naming to **0.9.3**. The supported game client remains
  CN HD **0.9.22.0.1 #1513**.
- Download `wot-0.9.22-offline-battles-0.9.3-Windows-x64.zip`. Close the old launcher,
  server and game, extract the complete ZIP into an empty folder, then run
  `wot-0.9.22-offline-battles.exe` and select the existing supported game directory.
- Let the launcher install the bundled update. Existing saves and user
  configuration are preserved. The complete English notes are included as
  `UPDATE_NOTES.md`.

# wot-0.9.22-offline-battles v0.9.5

This is the cumulative changelog **since the published v0.9.4 release**. The release follows PR #40 and its targeted repair branch, excluding the later abandoned PR branches. It supports only the Chinese HD World of Tanks **0.9.22.0.1 #1513** client.

## Bot tactics editor

The launcher now has a visual editor for Bot behavior, attack routes and artillery parking. Open **Tools → Bot tactics → Edit behavior, routes and artillery positions**.

- Edit all **41 supported maps** using the original minimap from the installed game when available. The editor shows real map bounds and team bases; a labelled navigation view appears if the minimap cannot be read.
- Copy a built-in attack route or draw a new one. Move or insert waypoints, mark hold points, and set vehicle classes, optional Bot slots, capacity, selection weight and a preferred or fixed route policy. The existing navigator still checks terrain and obstacles; fixed routes keep the intended lane except when combat or emergencies require a change.
- Draw artillery parking areas with a radius, initial heading and priority. The worker looks for reachable space large enough for the vehicle inside the area. Manual areas can be authored on all 41 maps. The supplied community position library covers **Ruinberg and Steppes** only; other maps keep their existing fallback until positions are authored.
- Set real Bot gunnery controls for every Bot, one team, a vehicle class or a specific team and slot. More specific rules override inherited values. The controls cover difficulty, crew level, reaction delay, aiming patience, convergence threshold, aim-point bias and lead error; they do not directly alter native damage, penetration, dispersion, spotting or reload.
- Keep named profiles outside the game folder, import or export JSON, and save a draft independently of **Apply**. The host reads an applied profile at the start of the **next battle**. Changes made during a battle do not change that battle; joining players use the host's plan. Subsequent edits do not require rebuilding the EXE.
- The editor follows the launcher's **Auto / English / 中文** language setting, including windows already open. Map and built-in route names switch language without changing route coordinates, drafts or user-authored names.

## Artillery firing and deployment

- Repair the SPG loop where a Bot repeatedly turned toward a known target, then back to its original direction, without firing because an advisory firing proof had expired. Moving-target proofs now refresh within bounds, and logging identifies the actual firing gate. Every shot still needs a loaded shell, real aim, a valid native trajectory and checks for cover and friendly vehicles.
- If a nearby wall is confirmed to block every firing arc, an SPG may make a limited move toward an existing safe waypoint. This does not invent a new destination or guarantee a firing solution.
- Supply source-labelled initial artillery parking areas for **Ruinberg and Steppes**. The worker selects them using the existing map grid, vehicle footprint and reachability checks; uncovered maps keep the previous fallback. Neither library nor manual areas teleport vehicles.

## Battle setup and Bot control

- Restore both `-2..0` and `0..+2` tier presets, select a legal window containing the connected human vehicles, and mirror tier and class slots across the teams. Automatic lineups may include zero to three SPGs per team, including human artillery. Offline room sampling does not reproduce the retail queue algorithm.
- Repair contact and impulse acknowledgement in the restored Bot, together with radio-recipient filtering. A contact report intended for another Bot no longer grants targeting or movement knowledge. Pushing uses the vehicles' actual mass, engine-powered approach, track response and shared collision result. The original v0.7.7 driving and traffic strategy and 41 navigation maps remain in use.

## Collisions, wrecks and battle feedback

- Repair high-speed rams where vehicles moved from the impact but HP did not change because the collision probe missed structural armour. The calculation samples matching native armour plates at a shared point within the contact overlap. Existing mass, horizontal closing speed, contact armour and damage factors remain; this release does not retune the global damage scale. Regression checks cover both mass directions and the hidden worker's contact path.
- Let a wreck continue moving across a narrow gap beneath its centre when both ends of the hull still have ground support. Repeated pushes reach the worker, and duplicate delivered impulses are ignored. Cliffs, solid barriers and vehicle-sized clearance remain checked. Wrecks do not lose HP.
- Distinguish HE hits that do not penetrate and cause no HP loss, hits that do not penetrate but deal blast damage, and penetrating hits that deal damage. Match voice feedback to the outcome and play the explosion on direct HE impacts as well as near misses.
- Make a retained player wreck block the reticle's ray during post-destruction spectating, preventing a false silhouette on a vehicle behind it.
- Correct the **Mittengard** base circle to its verified 30 m radius. Read team-specific **Tundra** and **Live Oaks** circle radii from the installed original map data.

## Garage, missions and supplies

- Feed human view ranges into Bot observations so the T28 Concept **HT-5** condition can evaluate damage dealt within the actual view range.
- Preserve the shell order selected in the garage service screen in both the battle gun and the authority worker's gun contract.
- Relay all-target premium consumable activation when a local vehicle model is temporarily unavailable, and log equipment rejection reasons for diagnosis.
- Correct free-experience conversion with zero-debit vehicles so it does not falsely mark unowned vehicles as newly elite. Requalification resets crew skills through the native descriptor while preserving the transaction accounting. Keep the exchange, crew and elite-notification corrections from the intervening builds.

## Installation and validation

Close the old launcher and game. Extract the **entire** `wot-0.9.22-offline-battles-0.9.5-Windows-x64.zip` into a **new empty folder**. Run `wot-0.9.22-offline-battles.exe` and select your existing #1513 game client. Do not merge old and new `_internal` directories. All LAN participants should use the same package. Existing save slots do not need to be reset.

The Windows build checks the server, Python 2.7 client payload, launcher, simulated #1513 installation and bundled-server startup. Focused collision and battle suites pass. The general Tests workflow still has a Bot gameplay follow-up failure also present on the untouched PR #40 baseline. CI and static tests do not replace native Windows gameplay checks for HE effects, mission completion, map rendering or repeated collision feel. This release does not claim to recover the private retail ram-damage formula or matchmaking queue.

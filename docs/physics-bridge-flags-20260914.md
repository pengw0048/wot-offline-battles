# 2026-09-14 第四份物理测试构建：车辆碰撞过滤

针对 `wot-error-report-20260914-132946-9d473a900b2e.zip`。报告中的客户端确认为第三份测试构建 `colorfulmeans-34807861243-1`；用户确认翻正后的方向反转已解决，本次聚焦里夫奥克斯铁路桥。

## 日志和代码证据

`44_north_america` 中，车辆沿轨道行驶时两排轮组分别获得约 5.014 米和 5.352 米的支撑。13:27:56 和 13:28:26 的卡住记录显示，偏离后会出现整排直接探测失效；其中多个探测范围仍包含桥面高度。之后车体侧倾、下沉，探测范围也随之落到桥下。

查到一个明确的引擎接口用法错误：车辆悬挂、车体运动及运动重投射一直给 `wg_collideSegment` 传入 `128`。第四个参数是要**跳过**的三角形标志；`128` 对应 `TRIANGLE_PROJECTILENOCOLLIDE`，不是“地形加静态建筑”的选择开关。它会把车辆应碰撞、炮弹可穿过的简化碰撞面排除掉。增加点位或沿旧高度补查仍用同一标志，所以不能找回被过滤的面。

标志定义依据：[BigWorld WorldTriangle 定义](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/3d3cc16ae60bb1d71cb014e9b0539e54e6d8c4fb/programming/bigworld/lib/physics2/worldtri.hpp)。车辆运动使用 `TRIANGLE_NOCOLLIDE` 的行为也见[引擎车辆/角色物理实现](https://github.com/v2v3v4/BigWorld-Engine-14.4.1/blob/3d3cc16ae60bb1d71cb014e9b0539e54e6d8c4fb/programming/bigworld/client/physics.cpp)。

仓库中该地图的 BSMO 碰撞标志统计确实包含 `0x4900`、`0x4980`、`0x4990` 等组合；其中 `0x49` 是材质类别的高字节。但错误报告没有具体桥梁模型和逐三角形标志，不能把这些统计直接当成每一片桥面的实测数据。桥面的剩余问题是否全部由此造成，仍需客户端复测。

## 修正

| 用途 | 跳过标志 | 行为 |
| --- | --- | --- |
| 车辆、悬挂、车体、导航及运动重投射 | `0x10 \| 0x40`，即 80 | 跳过非实体装饰和水面，保留车辆专用碰撞面 |
| 炮弹和现有视线探测 | 原有 128 | 继续按原有炮弹/视线语义工作 |

所有运动查询共用 `collision_flags.VEHICLE_SKIP_FLAGS`。破坏轻型障碍物后检查后方实体的重投射也使用相同规则，避免第一条射线正确、第二条又漏掉护栏。没有扩大桥面边界、延长地面记忆或添加不可见平台。

卡住日志增加 `motion_skip_flags`、每轮平面高度上限，以及原始层的高度、法线 Y 和接受/拒绝原因。这些数据来自已有射线，不增加原生探测次数。

## 验证范围

新增模拟场景实际执行三角形位标志过滤，而此前桥面测试忽略了这个参数。覆盖整片车辆专用桥面、可供炮弹碰撞的窄铁轨、非实体装饰、水面、桥底，以及 30/120 Hz 和 2/20 米每秒下的横向偏移行驶、驶离桥端及侧边。另验证 Bot 支撑、桥下通行、车体护栏碰撞、轻型障碍物后的护栏重投射和炮弹穿过车辆专用面。

将三处运动标志临时替换回旧值 128，五个新增测试均能检出错误；恢复修正后通过。本地 1,873 项客户端、Bot、悬崖、翻车恢复、碰撞和破坏物相关回归通过；完整测试及 Windows 打包由测试分支 CI 执行。

本环境没有该版本客户端地图包，也不能运行 Windows 原生游戏。上述结果是代码和模拟几何验证，不是里夫奥克斯实机通关验证。

## 使用

退出旧启动器及游戏，完整解压 r4 测试包一次，运行根目录 `wot-0.9.22-offline-battles.exe`，选择原来的 0.9.22.0.1 #1513 游戏目录。重点复测偏离铁轨后的桥面行驶、转向和桥梁接缝。

# 0.8.1 战斗问题修复测试版（2026-09-14）

基于已发布的 0.8.1 提交 `146c2b6c1090370c521c9b3267d8647c2ff72678`。
版本号保留 0.8.1，通过构建标识区分测试包；这不是新的正式 Release。
本次提供的错误报告记录的是 0.8.0 运行组件，不能据此断言所有问题在原版 0.8.1 中仍然存在。

## 16:57 报告追加修复

首个测试包 `colorfulmeans-34824012535-1` 进入战斗后立即返回车库，两个回合均在弹药栏初始化时报出 `GunShot.get -> AssertionError: Operation is not allowed`。0.9.22 #1513 客户端的 GunShot 禁止字典接口，本次改用其原生 `shell`、`speed` 属性。弹速附加信息出错时保留原生提示，避免显示层异常中断弹药更新和战斗。

同一报告还显示 `VISIBLE COMMAND rejected ... type=worker_ping`：延迟测量处理函数已经存在，但服务器可见客户端入口没有放行请求。本次补入消息列表，保留仅隐藏客户端可回应的身份校验。新增测试覆盖已安装的弹药栏钩子、原生属性对象，以及真实 TCP 入口到隐藏客户端回应的完整路径。

## 改动

1. 战绩：补齐被击穿、无伤害直接命中、溅射命中统计，贯通服务器、战绩回执和原生详细战绩字段。旧回执缺失字段时兼容为零。
2. 可破坏物：针对穆勒万卡日志中的实际物件编号与烘焙编号错位，按原生类别和完整变换矩阵逐项验证后重建索引，同时更新树木、物件、碰撞空间索引及流式缓存。不能唯一确认的物件不尝试强制销毁；没有编号异常的区块沿用原路径和原有查询预算。
3. 尸体：收到推移后的尸体快照时，同时更新保留的原生呈现位置，让模型、车体碰撞与后续同步使用同一位置。
4. Ping：战斗左上角显示可见客户端经服务器到隐藏模拟客户端主循环再返回的往返延迟，包含隐藏客户端主循环排队时间。响应长时间停滞时显示高延迟和卡顿标记。原有服务器网络延迟仍供内部同步使用。
5. 火炮 HE：有伤害但未击穿的直接命中使用有伤害爆炸反馈，不再按普通未击穿播放语音；零伤害、其他车型和非 HE 炮弹保留原逻辑。
6. 弹药提示：战斗中鼠标悬停炮弹时显示当前安装火炮、对应弹种的实际弹速，单位为米/秒。
7. 火炮 Bot：移除自动阵容中禁用火炮的默认值，恢复每队最多三辆火炮，并计入该队真人火炮；保留已有弹道、射界、友军遮挡和开火确认逻辑。

## 游戏内复测

适用客户端：国服高清 0.9.22.0.1 #1513，32 位。将完整测试 ZIP 解压到新目录，从解压后的启动器运行，避免混用旧目录组件。

- 在穆勒万卡驶过报告附近的围栏、草垛和树木，分别测试碾压、射击；绕行后再次接近，确认碰撞与外观一致。发生编号修复时日志会出现 `DESTR live layout`。
- 推动敌方坦克尸体数米，再从侧面接触和向新旧位置射击，确认旧位置没有残留碰撞。
- 使用火炮 HE 分别制造直接命中有伤害、溅射有伤害、完全无伤害，并检查语音、战绩和炮弹悬停提示。
- 创建可选车辆池含火炮的对局，确认阵容生成火炮 Bot，并观察其瞄准、开火和命中。小阵容或车辆池不足时不保证一定抽中火炮。
- 比较左上角 Ping 与隐藏客户端繁忙时的响应；该数字是整个模拟往返时间，不等于隐藏客户端 FPS 或单程网络延迟。

自动化测试验证协议、统计、索引恢复、提示及反馈分支。当前开发环境不能运行 WoT 原生客户端；树木倒伏表现、原生碰撞、实际语音和火炮 Bot 实战表现需要游戏内复测。

# 2026-09-14 第三份物理测试构建

基于第二份测试包 `colorfulmeans-34804431242-1`，对应 12:33 错误报告。

## 报告确认的问题

`37_caucasus` 中，翻正后的车体仍使用约 `pitch=3.13, roll=-3.13` 的姿态，之后俯仰角还累计到了约 9.3 弧度。这些姿态在画面上可以接近正立，但车头实际朝向与只用旧 yaw 计算的驱动方向相反。

客户端四次确认了坦克之间的装甲接触，服务器在 12:29:45、12:29:54、12:30:03 和 12:30:21 均记录 `RAM CONTACT ... reason=malformed_contact`。接触记录中的翻滚角度超出了原有倾角校验范围。

`44_north_america` 铁路区域仍出现桥内卡住和下落。第二份构建的补查仅围绕单个轮组曾经读到的高度上下 12 厘米进行；未曾命中桥面、已读到下层横梁、以及桥面略高于入口时，补查仍有缺口。报告没有完整的逐轮原生射线结果，不能仅凭这些日志确认每个桥面三角形的具体行为。

## 本次修正

- 在驱动、悬挂结算后的碰撞及最终姿态发布处，把完整 YPR 姿态转换到车头投影与航向一致的角度表示。同步变换有符号速度和俯仰角速度，保持世界中的惯性和车体实际朝向。
- 撞击记录单独执行相同姿态转换。翻正后的记录能够通过原有服务器校验，无须放宽装甲、接触位置、速度或记录时序检查。
- 铁路支撑补查覆盖相邻轮组之间的履带段，并限制在底盘范围内。单个轮组丢失记忆时可参考整车最近确认的支撑层，但必须有新射线命中真实的向上表面才能建立支撑。
- 补查允许不超过离地间隙、且最多 35 厘米的局部高差，用于进入略高的轨道和桥面。驶离桥端后仍释放支撑并受世界竖直重力作用。
- 卡住日志附带十个弹簧位置、查询高度范围及补查前后的支撑结果，方便实际地图复测时直接区分漏查、错误层和支撑失效。

平地撞击建筑物不扣血的行为保持；腾空撞击、坠落和坦克之间的撞击继续走各自已有的伤害结算。

## 验证

新增测试覆盖正向与反向翻滚后落地、侧向翻滚后恢复行驶、YPR 全车坐标轴与世界速度保持一致、实际客户端撞击记录到服务器校验，以及旋转方向的稀疏桥面、入口 24 厘米高差、下层横梁、枕木间隙和驶离桥端。场景在 30/120 Hz 及不同车速下运行。

将对应逻辑替换回第二份构建，三个新场景分别重现了方向反转、`malformed_contact` 和跌入桥面的问题。新逻辑通过这些场景。现有悬崖、车顶接地、斜坡、碰撞和服务器相关回归也随构建运行。

这些是模拟几何与运行时代码测试。本环境不能运行 WoT 的 Windows 原生地图引擎，铁路桥仍需在实际客户端复测；此包不代表已完成游戏内验证。

## 使用

完整解压测试包一次，运行根目录 `wot-0.9.22-offline-battles.exe`，选择原来的 0.9.22.0.1 #1513 游戏目录。启动器会安装本次测试补丁。

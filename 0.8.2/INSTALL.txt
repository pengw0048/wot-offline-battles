World of Tanks 0.8.2 native bot physics experiment 1.8.59
=========================================================

Use START_HERE.txt for the shortest startup path. This is not a stable release;
the version-pinned native bridge rejects an incompatible WorldOfTanks.exe
automatically.

Client installation (repeat on every Windows machine)
------------------------------------------------------

1. Close the game.
2. Delete or move aside <game root>\res_mods\0.8.2.
3. Copy this package's complete 0.8.2 folder into <game root>\res_mods.
4. Start the game and open LAN SETTINGS in the upper-right of the hangar.
5. Enter the server IP and TCP port, enable LAN Battle, then click SAVE.

Expected entry file:

    <game root>\res_mods\0.8.2\scripts\client\gui\mods\mod_offhangar.py

There must not be a mod_offhangar.pyc next to that file. Keep both
scripts\client\CameraNode.pyc and scripts\client\OfflineEntity.pyc: they are
Python 2.6 compatibility entry points required by this client. No external
Python installation is needed on client-only machines.

Start the included server
-------------------------

Replace every older client package and lan_battle_server.py with the files in
THIS package. Protocol 8 and client build
1.8.59-native-experimental-20260815 are intentionally incompatible with older
client/server builds, so every player and the server must use this same package.

Install Python 3 from https://www.python.org/downloads/ on the one machine that
will host LAN battles. Then double-click RUN_SERVER.bat on Windows or
RUN_SERVER.command on macOS. The equivalent terminal command is:

    python3 lan_battle_server.py --host 0.0.0.0 --port 28782

Windows may use `python` instead of `python3` if that command launches Python 3.
Allow TCP port 28782 through that machine's firewall when prompted.

Waiting room and battle start
-----------------------------

1. Click Battle! on every client that should join.
2. Confirm one JOIN line per machine in the server terminal.
3. In the clickable waiting-room panel, choose one of the 33 stock maps.
4. Click START BATTLE; the server sends that map and roster to every client.

The old F12 and 0-key start shortcuts are not used by this build.

Bots in this build
------------------

- Standard base-capture battles are supported; assault and encounter variants
  are intentionally outside this build.
- All 33 stock maps ship with validated tactical routes and prebaked terrain
  navigation graphs.
- Bounded weighted A* follows those graphs while local feelers avoid cliffs,
  deep water, hard obstacles, nearby tanks and congestion. Shallow fords are
  allowed only at an explicit extra path cost.
- Vehicle roles cover brawling, support, flanking, sniping, scouting and SPGs.
- Each team has at most one SPG, including any SPG selected by a LAN player.
- Bots have stable individual aggression, caution, teamwork and driving habits.
- Combat behavior includes limited spotting information, target memory, hull
  angling, peek-and-withdraw timing and occasional forward/backward jiggling.
- The same smart AI runs in normal offline battles and in a one-player or
  multiplayer server-backed room.

LAN synchronization
-------------------

- The server owns global target reservations, route progression, revisioned bot
  orders and static weighted-A* paths over the shipped navigation graphs. One
  elected client supplies limited spotting observations and executes exact map
  collision, local steering, shell/armor and battle-rule work.
- Every client receives shared bot identity, movement, aiming, firing, HP,
  deaths, wreck positions, capture progress and the final battle result.
- If the authority disconnects, the server elects another connected client.
- Human input, bot state and server snapshots run at 30 Hz. Clients interpolate
  remote vehicles every render frame with bounded prediction.

Current boundary
----------------

This is a trusted-LAN implementation, not the original retail BigWorld server.
The elected client still owns native map collision, short-range steering,
combat execution and client physics. Hidden runtime state is not preserved
perfectly across authority failover, and complete
module/crew synchronization, reconnection recovery, anti-cheat, NAT traversal
and internet-safe authentication are outside this build. See LAN_SERVER.md for
detailed diagnostics and the protocol boundary.
